# ToDoList

Учебный REST API на Go для списка задач. Можно создавать пользователей, добавлять им задачи, менять их и отмечать выполненными. Данные хранятся в PostgreSQL.

Ещё есть статистика: сколько задач создано и выполнено, процент выполненных и среднее время выполнения. Её можно посмотреть для отдельного пользователя и за нужный период.

## Что использовал

- Go и стандартный `net/http`
- PostgreSQL, для работы с базой — `pgx`
- Docker Compose
- Swagger для документации и проверки запросов
- Zap для логов

## Как запустить

Нужны Docker с Compose и `make`. Все команды выполняются из корня проекта.

Создать файл `.env`. Например, для локального запуска:

```env
POSTGRES_USER=todoapp
POSTGRES_PASSWORD=todoapp
POSTGRES_DB=todoapp

HTTP_ADDR=:5050
HTTP_SHUTDOWN_TIMEOUT=30s
LOGGER_LEVEL=DEBUG
POSTGRES_TIMEOUT=10s
```

Поднять базу:

```bash
make env-up
```

Применить миграции и запустить приложение (Compose автоматически дождётся готовности PostgreSQL):

```bash
make migration-up
make todoapp-deploy
```

При запуске `make todoapp-deploy` база также поднимается автоматически, если была остановлена. Перед первым использованием по-прежнему нужно применить миграции.

Если приложение сообщает `lookup postgres-app ... no such host`, проверьте контейнер базы и запустите сервисы из одного Compose-проекта:

```bash
docker compose ps -a postgres-app todoapp
docker compose logs --tail=50 postgres-app
make todoapp-deploy
```

Если PostgreSQL не запускается, причина будет в его логах. Каталог `out/pgdata` содержит данные базы; для восстановления запуска удалять его не требуется.

API будет доступен по адресу `http://localhost:5050/api/v1`.
Swagger: [http://localhost:5050/swagger/index.html](http://localhost:5050/swagger/index.html).

## Что есть в API

| Метод | Путь | Что делает |
| --- | --- | --- |
| POST | `/users` | Создать пользователя |
| GET | `/users` | Получить список пользователей |
| GET | `/users/{id}` | Получить пользователя |
| PATCH | `/users/{id}` | Изменить пользователя |
| DELETE | `/users/{id}` | Удалить пользователя |
| POST | `/tasks` | Создать задачу |
| GET | `/tasks` | Получить список задач |
| GET | `/tasks/{id}` | Получить задачу |
| PATCH | `/tasks/{id}` | Изменить задачу |
| DELETE | `/tasks/{id}` | Удалить задачу |
| GET | `/statistics` | Получить статистику задач |

Все пути в таблице начинаются с `/api/v1`. У списков есть параметры `limit` и `offset`, у статистики — `user_id`, `from` и `to`. Даты передаются в формате `YYYY-MM-DD`.

Сначала нужно создать пользователя, а потом передать его `id` в поле `author_id` при создании задачи. Чтобы отметить задачу выполненной, отправить PATCH с телом:

```json
{
  "completed": true
}
```

## Структура проекта

- `cmd/todoapp` — запуск приложения
- `internal/core` — общие типы, настройки, HTTP-сервер и подключение к базе
- `internal/features` — пользователи, задачи и статистика; внутри обработчики, сервисы и запросы к базе
- `migrations` — SQL-миграции
- `docs` — сгенерированная документация Swagger

## Полезные команды

```bash
go test ./...           # запустить тесты (нужен Go версии из go.mod или новее)
make swagger-gen       # обновить Swagger после изменения аннотаций
make todoapp-undeploy   # остановить приложение
make env-down          # остановить базу
```

## Web-интерфейс

После запуска приложения откройте [http://localhost:5050/](http://localhost:5050/).
Интерфейс встроен в Go-бинарник через `go:embed`: Node.js, сборка frontend и отдельный сервер не нужны.

- **Задачи**: создание, просмотр и редактирование, удаление с подтверждением, отметка выполнения и возврат в работу, поиск по названию/описанию и фильтры по автору и статусу.
- **Пользователи**: создание, редактирование имени/телефона, поиск и удаление. При удалении пользователя удаляются и его задачи — интерфейс предупреждает об этом.
- **Статистика**: количество созданных и выполненных задач, процент выполнения, среднее время и графическая шкала прогресса. Фильтры по пользователю и датам; начало включается, конец не включается.

Сначала добавьте пользователя, затем создайте задачу с ним в качестве автора.
Пустые телефон и описание сохраняются как `null`. Автор существующей задачи не меняется (это ограничение API).
Изменения сохраняются через `/api/v1` в PostgreSQL. Ошибки отображаются рядом с формами; кнопка «Обновить» повторно загружает данные.

Файлы интерфейса находятся в `internal/webui/static`. После их изменения пересоберите приложение (`make todoapp-deploy` или `make todoapp-run`).
